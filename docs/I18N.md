# i18n status: Applies — deferred to the first public web release

Reason: ReuseProof CA is planned for California jurisdiction staff and public
report readers, so its future human-facing workflow has a language-access
obligation. The currently shipped TypeScript library has no message catalog or
locale selector; that is a visible pre-release gap, not an N/A exemption.

## Boundary

Machine schema keys, content hashes, receipt identities, enum values, source
text, and canonical JSON remain locale-independent. Localizable content
includes application navigation, validation explanations, public summaries,
complaint instructions, report prose, dates, numbers, and units.

User-authored and authoritative source text retains a BCP 47 language tag and
is never silently replaced by translation.

## Entry point and gate

The first public web release must introduce a MessageFormat 2/FormatJS message
boundary, explicit locale negotiation with deterministic English fallback, and
reviewed English and Spanish catalogs. `make verify` must gate key,
placeholder, and plural parity; valid BCP 47 tags; pseudolocale expansion; RTL
layout readiness; and locale-aware dates, numbers, and units.

Spanish public and regulatory terminology requires human review by a
California water/public-health translator and a community representative.
Unreviewed machine translation may not ship as authoritative or public text.
